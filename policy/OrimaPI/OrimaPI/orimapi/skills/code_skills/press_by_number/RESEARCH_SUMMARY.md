## 任务及职责

GPT从当前RGB读两张数字卡，确定第一红按钮A、第二红按钮B和蓝色确认C。
执行器承担完整顺序：`A×na → C → B×nb → C → 双臂归位`。
两组之后分别确认，共两次蓝色按钮；每次必须下降并充分释放，不允许额外补按。

工具：

- `set_task_plan`：记录当前数字与按钮对应关系。
- `inspect_image`：当前图像局部放大，输出仅作识别，不用于标定像素坐标。
- `measure_button`：从标定RGB测量当前按钮表面；支持自动纹理/圆环和显式双目。
- `execute_counted_press_sequence`：使用三个表面与目标次数，完成整套按压及归位。
- `review_contact`：查看当前episode保存的before/down/released/abort图像。
- `move`、`point`：必要的空手观察姿态调整；`home`用于合法收尾或异常清理。

当前episode的结构化账本区分attempted、completed_motion_cycles和retry_safe。
运动循环次数不是可读取的官方触发次数。发生可能接触后禁止从头重放整组，
不知道是否按过也不能当作零次。最终成功只取原生结果。

## 成功路径和效率修复

1. 在接触前读卡并测量三个按钮，位置和次数不来自历史场景。
2. 将物体表面与名义TCP分开，通过公开指尖偏移计算接触姿态。
3. 在只读虚拟双臂状态中预检查当前姿态到完整按压及最终归位的机器人路线。
   通过才复用拍照姿态，否则预检查并使用归位准备路线；每个实际动作仍检查安全。
4. 已对准down/open-x的姿态不重复定向。首次下降连续有界加深，建立该按钮
   在本场景内的端点；下探子步骤没有中间释放，不算多次按压。
5. 接触适配器统一取2至4步稳定反馈；外层消费此证据，不叠加重复等待。
   释放和缓存往返端点仍保留2步稳定等待。
6. 左臂完成A后归位让出空间，右臂完成C/B/C，最后双臂归位。

首版首次按压开始于287/294步，第二版提前至192/152步。
首版seed1因预算不足只完成A9/C/B3；第二版在526步完成完整任务。
预算估计纳入本地关节细分、夹爪和等待步数，自适应余量单独报告。
估计仍依赖接触与控制假设，不是任何场景都能完整执行的保证。

## 失败经验与限制

- 旧正式v3曾在第一次接触不确定后请求尚未接入的阶段图像查看能力，随后停止。
  本版本已实际记录这些图像，而非只把能力写进提示词。
- 旧版也曾由GPT认为计数正确，原生仍失败。不能把看见按钮抬起、TCP到位、
  一段程序返回成功，直接解释为确切的按钮触发。
- 第一研究版虽减少模型交互，但重复准备和稳定等待消耗过多动作。
  保留失败证据，不将其结果并入当前版本资格。
- 接触受限只是反馈，不是激活传感器。保留原有轴向范围、横向/姿态检查，
  关节/桌面/碰撞限制及18mm下探上限，未通过增加力或放宽安全限制获取成功。
- 某次初始下探达到深度上限仍可能没有可靠激活证据；缓存端点也不能无限复用。
  本次小样本成功不排除新布局、遮挡、高计数组合或物体移动时的失败。
- 原生成功可能中断最终归位动作，使工具输出episode_over；以原生结果判定，
  不将这类终止一律算作控制失败，也不反过来把任何episode_over当作成功。
