# swap_blocks 子 skill

## 目标与接口

三张垫子、两个方块：利用初始空垫交换两个方块；每次搬运后按压并释放按钮一次，
共三次，最后双臂归位。使用当前三路 RGB、公开标定、机器人状态和原生 cuRobo。
GPT 选择当前参数与阶段；完整工具承担动作执行与反馈，不要求逐关节请求 GPT。

## 必需工具

- `rgb_point`：当前双视图三角化或条件水平表面测量。
- `transfer`：接近、下降、闭合稳定检查、抬升、搬运、放置、释放、撤回。
- `tap`：接近、下压、停留、卸载、撤回；最后一次可归位。
- `move` / `point`：有必要时调整空手观察位置和姿态。
- `rest`：合法归位或恢复；`gripper`：显式夹爪控制。
- `press_surface`：可选位移/回弹视觉验证，不是成功前身实际采用的必需路径。
- `rgb_ray` / `table_plane`：按需辅助测量；`obs` / `status` / `wait` / `done`：
  当前观察、反馈、必要等待和策略退出。

## 成功路径

记住 MA、MB、ME 和 A/B 身份。执行
`A→ME / tap-retract / B→MA / tap-retract / A→MB / tap-home`。
位置、深度与对应点必须来自当前场景；不能固化历史坐标。前两次不做不必要的
完整归位，最后一次保留按压与归位预算。详见 program_prompt.md。

## 失败经验

1. 测量接口通不等于执行接口通，必须验证动作出口与观测回传。
2. 静态像素/完整圆环会在接触时遮挡；使用适合操作的验证，不盲目循环测量。
3. 中途归位、慢速接触与过高悬停可能耗尽 700 动作，必须预算全任务。
4. 跨侧搬运要先保证闲置手臂不阻挡；不能靠降低碰撞阈值求分。
5. 闭合偏移失败需要改变有证据支持的抓取，而不是忽略错误。
6. 未确认的按压不能通过额外重复次数“补齐”。

## 运行与发布

工具及数值辅助代码全部随 bundle 分发，不引用研究目录或另一个方案的安装。
依赖仍包括项目机器人标定、现有模型接口及 RoboDojo/cuRobo 仿真 Python 环境。
可用 `code_parameters.native_ik` 显式指定 python、simulator_root、device；
缺省路径由公开机器人资源位置推导。新批次的双 GPU runtime view 重映射 device。

只要复测未成功，不替换正式 skill。发布时保留旧版归档、测试结果证，
将“用户授权单次复测发布”与“三 seed 资格”分开。
